# 08. Решения по пилоту Mythrix

Зафиксированные решения по стартовой реализации ИИ-DM.

## Язык

**Русский.** Вся Библия Мира, системный промпт, нарратив, синтетика —
на русском. Английские источники (Critical Role и т.п.) использовать
только как стилевой референс, без прямого попадания в датасет.

## Целевая модель

В проекте есть две модели (см. `feature/src/main/java/com/pimenov/feature/api/ModelDownloader.kt`):
- Qwen 2.5 **0.5B Instruct** — быстрая, 560 МБ
- Qwen 2.5 **1.5B Instruct** — умная, 1700 МБ (**это потолок**)

Старшая модель проекта = **Qwen 2.5 1.5B**. Все архитектурные решения
оптимизируются под её ограничения:
- формат `[NARRATIVE] + [EVENTS]` течёт ~30-40% → обязательны валидация + retry
- системный промпт должен быть жёстким, с few-shot примерами
- fine-tune (LoRA) понадобится раньше, чем для 7B (триггер: ≥1000 примеров)

## Стартовый сеттинг для пилота — Таверна

Существующий Dragon Tower **на время пилота не используется** —
делаем изолированную тестовую среду «Таверна».

### Локация
**`loc_tavern_starting`** — единственная локация в пилоте.
Атмосфера: печальная, в воздухе веет смертью. Дракон разрушил
окрестности, продовольствия мало, таверна скоро закрывается.

### NPC (5 шт.)

1. **Трактирщик** (`npc_tavern_innkeeper`) — торговец.
   Инвентарь: меч, щит, лук, топор, припасы для восстановления HP.
   Подзывает героя при входе: «Что тебе, путник? Мы скоро закрываемся,
   дракон разрушил все продовольствия и у нас не так много припасов».

2. **Шахтёр 1** (`npc_miner_1`) — пустой взгляд, выпивает, тихо говорит
   с шахтёром 2 про дракона, который убил их жён, пока они были в шахтах.
   Не агрессивен, делится горем если спросить.

3. **Шахтёр 2** (`npc_miner_2`) — то же состояние, дополняет шахтёра 1.

4. **Воин 1** (`npc_warrior_1`) — при оружии, ждёт часа выступить
   против дракона. Понимает, что идёт на верную смерть. Хмурый,
   немногословный, может присоединиться к мотивации героя.

5. **Воин 2** (`npc_warrior_2`) — аналогично, дополняет воина 1.

### Сюжетная задача пилота
Через диалоги с NPC у героя должна **сформироваться мотивация**
победить дракона. Это и есть тест: умеет ли DM подвести игрока к
эмоциональному решению через атмосферу и реплики NPC, не диктуя
ему действия.

## Что тестируем на пилоте

1. **Удержание канонов.** DM не выдумывает 6-го NPC, 3-го воина,
   не предлагает «эльфа в углу».
2. **Удержание атмосферы.** Каждая реплика поддерживает «веет смертью»,
   не скатывается в стандартное «привет, искатель приключений!».
3. **Формат вывода.** Сколько раз из 100 ходов JSON валиден с первого
   раза, сколько — после retry, сколько — провал.
4. **Двухфазный бой.** Если игрок задирается на воинов — корректно ли
   проходит attack-intent → расчёт → описание исхода.
5. **Граница сцены.** Срабатывает ли `scene_ended=true` при выходе
   из таверны (когда игрок решит идти к дракону).

## Что отложено за пределы пилота

- Множественные локации и переходы.
- Полная Библия Мира Dragon Tower.
- Векторизация и RAG (на пилоте достаточно жёсткого фильтра —
  всё помещается в окно 32k).
- Сбор реальных логов (только синтетика + ручные тесты).

## Стилевые референсы для системного промпта

**От пользователя ожидается** список 2-3 имён/каналов/книг как
стилевой эталон DM. На момент фиксации не указан → попросить отдельно
перед написанием системного промпта.

Кандидаты для анализа (с открытых источников, требует WebFetch):
- aternia.games/materials — сюжеты
- RPG-Zone.ru — диалоги
- Imaginaria.ru — диалоги

План: спарсить 5-10 фрагментов, показать пользователю, он выбирает
1-2 как эталон для few-shot в системном промпте.
