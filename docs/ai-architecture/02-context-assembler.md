# 02. Сборщик контекста (реляционный RAG)

**Статус (2026-05-23):** реализовано как **реляционная выборка** в
`TavernWorldBibleLoader` (де-факто ContextAssembler). Векторный поиск
(эмбеддинги, sqlite-vec, EmbeddingGemma) **отменён** вместе с локальной
моделью — для структурированной Библии Мира релевантность берётся по связям
`id`, а не по семантике. Раздел про семантический поиск ниже оставлен как
исторический.

## Что реально подаётся в промпт (реализовано)

Не вся Библия Мира, а только релевантное текущей сцене:
- `[PLAYER_STATE]` — игрок с живыми полями (hp, золото, инвентарь, стадии).
- `[ЖУРНАЛ]` — компактный recap прошлых сцен.
- `[LOCATION]` + `[ВЫХОДЫ]` — текущая локация, её атмосфера и связанные выходы.
- `[NPCS]` — только NPC, физически присутствующие в текущей локации.
- `[ВРАГИ]` — враги текущей локации.
- `[ITEMS]` — предметы у игрока / в текущей локации / у присутствующих NPC
  (купленное переустановлено на `player_main`).
- `[QUESTS]` — квесты `active`/`available` или связанные с локацией/NPC сцены.

## Шаг 1. Жёсткий фильтр (без векторов)

Всегда грузится:

1. **`player.json` целиком** — корень контекста. Через его поля
   автоматически тянутся связанные сущности:
   | Поле | Что подтягивает |
   |---|---|
   | `location_id` | текущую локацию + её NPC + предметы |
   | `inventory` | полные карточки предметов из items.json |
   | `active_quests` | quest-объекты + текущую стадию |
   | `known_npcs` | краткие карточки (имя + где видел) |
2. Активные квесты (`quests.status = active`)

## Шаг 3. Саммари диалога

Из менеджера контекстного окна (см. `03-context-window-management.md`).

## Что векторизуем

Каждая сущность Библии Мира → один текстовый чанк + вектор.
Длинные сущности режутся на 2-3 чанка.

Пример чанка для NPC:
```
[NPC] Орм Привратник — старый орк со шрамом, охраняет
врата Драконьей Башни уже сто лет. Грубый, говорит
коротко. Знает о квесте «Сердце дракона».
```

## Хранилище

Таблица `world_chunks` в той же SQLite (через sqlite-vec):

| Поле | Тип |
|---|---|
| id | TEXT |
| entity_id | TEXT (FK на JSON) |
| entity_type | TEXT (npc/location/item/quest/lore/event) |
| location_id | TEXT (для быстрой фильтрации) |
| text | TEXT (что показываем DM) |
| embedding | VECTOR(384) |

**Источник правды** — JSON-файлы. При изменении сущности чанк
пересчитывается и вектор обновляется.

## Финальная структура промпта

```
[SYSTEM]              ← системный промпт DM (статично)
[STYLE EXAMPLES]      ← 1-2 few-shot по atmosphere.mood локации
[PLAYER]              ← из player.json (всегда)
[CURRENT SCENE]       ← локация (с atmosphere.nuance) + NPC + предметы
[ACTIVE QUESTS]       ← все active
[RELEVANT MEMORY]     ← top-5 из RAG
[SCENE SUMMARY]       ← саммари текущей сцены (если есть)
[RECENT MESSAGES]     ← последние 6-10 реплик дословно
[PLAYER ACTION]       ← ход игрока
```

## Подбор few-shot по атмосфере

Few-shot примеры эталонного DM-нарратива хранятся в библиотеке,
структурированной по `mood`:

```
few_shots/
  somber/    — печальные, тяжёлые сцены (Фрагмент 1 трюм, Фрагмент 5 шторм)
  dangerous/ — бой, погоня
  cheerful/  — праздник, ярмарка
  tense/     — напряжённое ожидание
  ...
```

Сборщик читает `current_scene.atmosphere.mood` и подкладывает 1-2 примера
из соответствующей папки в блок `[STYLE EXAMPLES]`. Это не даёт DM
нагнетать в весёлой таверне или шутить на похоронах.

Диалоговые приёмы (обрывистая речь, недосказанность) хранятся отдельно
в `dialogue_examples/` без привязки к mood — они универсальны.

## Технологии

- **sqlite-vec** — расширение SQLite, ставится поверх существующей
  Room-базы. Не требует отдельной инфраструктуры.
- **EmbeddingGemma-300M** — локальный эмбеддер, 300M параметров,
  размерность вектора 384.
