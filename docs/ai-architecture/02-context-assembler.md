# 02. Сборщик контекста + RAG

Перед каждым запросом к ИИ-DM собирается промпт из двух источников:
жёсткий фильтр (всегда) и семантический поиск (top-K по фразе игрока).

## Шаг 1. Жёсткий фильтр (без векторов)

Всегда грузится:

1. **`player.json` целиком** — корень контекста. Через его поля
   автоматически тянутся связанные сущности:
   | Поле | Что подтягивает |
   |---|---|
   | `location_id` | текущую локацию + её NPC + предметы |
   | `inventory` | полные карточки предметов из items.json |
   | `active_quests` | quest-объекты + текущую стадию |
   | `known_npcs` | краткие карточки (имя + где видел) |
2. Активные квесты (`quests.status = active`)

## Шаг 2. Семантический поиск (RAG)

- Векторизуем фразу игрока моделью EmbeddingGemma-300M.
- Ищем top-5 ближайших чанков в локальной векторной БД.
- Фильтруем дубли с шагом 1 (уже подтянутые жёстким фильтром).

## Шаг 3. Саммари диалога

Из менеджера контекстного окна (см. `03-context-window-management.md`).

## Что векторизуем

Каждая сущность Библии Мира → один текстовый чанк + вектор.
Длинные сущности режутся на 2-3 чанка.

Пример чанка для NPC:
```
[NPC] Орм Привратник — старый орк со шрамом, охраняет
врата Драконьей Башни уже сто лет. Грубый, говорит
коротко. Знает о квесте «Сердце дракона».
```

## Хранилище

Таблица `world_chunks` в той же SQLite (через sqlite-vec):

| Поле | Тип |
|---|---|
| id | TEXT |
| entity_id | TEXT (FK на JSON) |
| entity_type | TEXT (npc/location/item/quest/lore/event) |
| location_id | TEXT (для быстрой фильтрации) |
| text | TEXT (что показываем DM) |
| embedding | VECTOR(384) |

**Источник правды** — JSON-файлы. При изменении сущности чанк
пересчитывается и вектор обновляется.

## Финальная структура промпта

```
[SYSTEM]              ← системный промпт DM (статично)
[PLAYER]              ← из player.json (всегда)
[CURRENT SCENE]       ← локация + её NPC + предметы
[ACTIVE QUESTS]       ← все active
[RELEVANT MEMORY]     ← top-5 из RAG
[SCENE SUMMARY]       ← саммари текущей сцены (если есть)
[RECENT MESSAGES]     ← последние 6-10 реплик дословно
[PLAYER ACTION]       ← ход игрока
```

## Технологии

- **sqlite-vec** — расширение SQLite, ставится поверх существующей
  Room-базы. Не требует отдельной инфраструктуры.
- **EmbeddingGemma-300M** — локальный эмбеддер, 300M параметров,
  размерность вектора 384.
